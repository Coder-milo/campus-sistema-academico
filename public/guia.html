Guía del sistema académico

Campus reúne la gestión institucional, la planeación y el seguimiento académico. El proyecto utiliza datos ficticios para la revisión de Ingeniería de Software II.

Recorrido por perfiles

  1. Administrador. Consulta Comunidad, crea un aula y prueba un código duplicado. El administrador puede ver el registro de cambios.
  2. Coordinador. Revisa Carga académica. Intenta asignar al docente de Ingeniería de Software II otra clase el martes entre 09:00 y 11:00. La carga de ejemplo de 08:00 a 10:00 impide guardar ese cruce.
  3. Docente. En Asistencia, abre la sesión de ejemplo y registra una lectura simulada. En Calificaciones registra 4,0, 4,0 y 5,0 para Valentina García. La ponderación 30/30/40 produce 4,4.
  4. Estudiante. Consulta el horario, la asistencia propia, la definitiva y el avance del plan. Usa Horarios para probar una inscripción.

Seguridad y datos

Las contraseñas se verifican con scrypt y una sal aleatoria. El navegador recibe una cookie de sesión. El servidor verifica el rol, valida los cambios y devuelve los datos que corresponden a la cuenta. PostgreSQL conserva los datos y el historial de operaciones.

El sensor sigue siendo una simulación. El proyecto académico utiliza cuatro cuentas de revisión. La operación institucional requeriría gestionar cuentas reales, establecer copias de seguridad y verificar la recuperación.
